LESSON 14 · TRANSFORMER · 2026.09.25

Decoder-only：为什么很多生成式大模型只保留 Transformer 的“解码器”一侧？

今天只解决一个问题：原始 Transformer 明明有“编码器＋解码器”，为什么很多生成式语言模型后来只用一条连续生成链？

最简单的定义

Decoder-only（仅解码器）模型，就是没有单独的编码器，而是把输入和后续生成放在同一条 Token 序列中，用一组重复的 Transformer 模块一步步预测下一个 Token。

先理解两个词

编码器可以先理解成“把输入整体读成内部表示”；解码器可以先理解成“根据已有内容继续生成输出”。原始 Transformer 同时有两者，Decoder-only 则只保留生成这一侧所需的主链。

一、先用“翻译”和“续写”建立直觉

原始 Transformer 最典型的任务是机器翻译：先把整句英文读完，再生成中文。这里很自然地分成两步——编码器负责读源句，解码器负责生成目标句。

但如果任务是续写“今天北京的天气……”，模型并不一定需要先做一套独立的“读完再转交”。它可以把已有文字放在同一条序列里，直接根据前文一步步接着写。这就是 Decoder-only 最直观的思路。

二、一张图看懂两种结构

结构差别不在“有没有理解”，而在信息怎样流动
Encoder–Decoder

输入文本 → 编码器整体处理 → 解码器一边参考编码结果、一边生成输出

经典例子：原始 Transformer、T5 等文本到文本模型
Decoder-only

提示词＋已有上下文 → 同一条序列中的因果 Attention → 预测下一个 Token → 再继续

经典例子：GPT 系列及大量现代生成式语言模型

这里最关键的是第二条：当前位置只能利用已经出现在它前面的内容，不能偷看还没有生成的未来 Token。这种“只看左边”的限制通常称为因果 Attention。

新词备注｜因果 Attention
今天只把它理解成“生成第 n 个 Token 时，只允许参考第 n 个位置之前已经出现的内容”。不需要掌握遮罩矩阵或公式。

三、为什么这种结构特别适合生成？

因为训练目标和实际生成方式非常一致：训练时不断学习“给定前文，下一个 Token 应该是什么”；使用时也正是“给定前文，继续生成下一个 Token”。同一套主干既处理输入，也处理自己刚刚生成的内容。

这并不意味着 Decoder-only 天生“更会理解”。它只是把理解和生成都放进同一条序列计算中。Encoder-only、Encoder–Decoder 和 Decoder-only 各有适用场景，不能把某一种结构写成所有模型的统一答案。

四、聊天界面背后，通常仍是一条 Token 序列

在典型 Decoder-only 聊天模型中，界面上不同角色的消息通常会在送入模型前，由聊天模板整理成一条连续 Token 序列，并用特殊标记表示不同角色和消息边界。模型实际处理的是格式化后的序列，而不是若干彼此物理隔离的输入框。

因此，前端界面的角色划分与模型内部的输入结构并不是一回事。角色标记能够影响模型行为，但具体效果还取决于训练方式、聊天模板和应用层控制。

五、正面概念讲清以后，再看三个常见误解

误解 01“Decoder-only 就是不理解输入，只会往后续写。”——它仍会根据整个可见前文形成表示；“only”说的是结构，不是能力。
误解 02“它就是把原始 Transformer 的 Decoder 原封不动留下来。”——现代 Decoder-only 模型通常去掉了面向独立编码器的交叉 Attention，并对层结构、归一化和位置机制做了大量改造。
误解 03“界面上不同角色的消息，在模型内部天然完全隔离。”——它们通常会被序列化到同一上下文中，只是通过角色标记和模板加以区分。

六、为什么这件事与网信法研究有关？

审计大模型时，截图里的“消息框”不等于模型实际收到的输入。

如果系统采用 Decoder-only 聊天模型，真正影响输出的是经过聊天模板整理后的完整序列：系统级指令、用户问题、历史消息、工具返回结果以及截断顺序，都可能共同进入上下文。只保存最后一句用户输入，往往不足以复现当时输出。

因此，在政务、金融、医疗等高风险应用中，运行留痕可以进一步记录模型版本、聊天模板版本、实际传入的消息角色与顺序，以及因长度限制被删除或截断的内容。这样才能把“界面上看见了什么”与“模型实际计算了什么”区分开。

七、把这一课转成两个研究问题

论文问题

从消息角色到线性 Token 序列：生成式AI指令层级的技术事实与法律解释

可研究不同角色信息如何在同一上下文中被表示，以及指令层级应在技术证据和责任判断中怎样证明。

智库问题

高风险大模型“实际输入”最小留痕规范

可研究是否应统一记录聊天模板、角色顺序、上下文截断、模型版本和工具返回内容，避免仅凭前端聊天记录开展事故复盘。
