Embedding：模型怎样把 Token 变成可计算的一组数字？

今天只解决一个问题：上一课里 Token 已经有了编号，为什么还不能直接交给模型计算，而要再变成一组数字？

先把 Embedding 记成一句人话

Embedding 就是把一个 Token 转成一组可供模型计算的数字。模型不是靠“看懂文字”工作，而是不断对数字做计算，所以 Token 进入模型主体之前，还要先完成这一步。

这一课先不要求你懂

你会看到“向量”这个词。今天先把它理解成“一组有顺序的数字”即可，不需要学线性代数；后面遇到向量数据库、相似度等内容时再继续展开。

一、为什么 Token 有了编号还不够？

上一课讲过，一段文字会先被拆成 Token，每个 Token 又对应一个编号。例如，我们可以假设“法律”这个 Token 的编号是 317，“模型”的编号是 842。这里的 317 和 842 只是标签：它们告诉系统“这是哪个 Token”，却没有直接告诉模型这些 Token 之间有什么关系。

如果把编号直接当成大小来理解，就会产生荒谬结果：编号 842 并不比编号 317“更重要”，也不意味着两个编号相差 525，就代表两个词的意义相差 525。编号只负责认人，Embedding 才开始给模型提供可以用于计算的表示。

二、先看一个最简单的例子

为了建立直觉，可以把 Embedding 想成一张很大的“数字表”。每一个 Token 编号，都能在表里找到属于自己的一行数字。

仅为机制示意，真实模型通常会使用更多数字
① Token“法律”
→
② Token ID假设编号是 317
→
③ 查 Embedding 表找到第 317 行
→
④ 得到一组数字[0.21, -0.48, 0.73, 0.06 …]

这些数字只是示意，不是任何真实模型里“法律”这个 Token 的实际数值。

模型接下来真正拿去计算的，不再只是“317”这个编号，而是这一整组数字。

三、“向量”到底是什么意思？

在大模型资料里，你很快会看到一句话：“Embedding 把 Token 映射成向量。”如果第一次学，很容易被“向量”两个字吓住。

今天先用最简单的定义：向量就是一组有顺序的数字。例如 [0.21, -0.48, 0.73, 0.06] 就可以看成一个很短的向量。真实模型中的向量往往更长，可能包含几百、几千甚至更多个数字。

新词备注｜维度
一组数字里有多少个位置，通常会被称为多少“维”。例如 [0.2, 0.5, -0.1] 有三个数字，可以先理解成“三维”。今天只需要知道这个意思，不需要做任何数学计算。

四、这些数字是谁写进去的？

通常不是工程师给每个词手工填写一串数字。模型训练开始时，这些数字可以先被初始化，然后随着训练不断调整。模型在大量训练样本中反复尝试预测、纠错，Embedding 表里的数字也会跟着变化。

因此，一个训练完成的模型，其 Embedding 中往往已经保存了某些从训练中学到的关系。早期词向量研究就发现，经过训练后，词语之间的语义和语法关系可以在数字表示的相对位置中表现出来。现代大模型的内部机制更复杂，但基本直觉仍然成立：这些数字不是身份证号，而是模型学习过程的一部分。

Token ID

回答“它是哪一个 Token”。主要作用是索引和定位。

Embedding

回答“模型从哪一组数字开始处理这个 Token”。这些数字会参与后续计算。

后续计算

模型还会结合位置和上下文继续改变内部表示，因此 Embedding 只是进入模型时的起点。

新词预告｜上下文表示
同一个 Token 在进入模型时可以从同一组初始数字出发，但放进不同句子后，模型会结合前后文继续计算，形成不同的内部表示。后面讲 Transformer、Attention 时再解释它是怎么做到的。

五、理解清楚以后，再看三个常见误解

误解 01“Embedding 就是给每个词编一个更复杂的号码。”——不对。号码只是身份标签；Embedding 中的一组数字会直接参与模型计算，并在训练中被调整。
误解 02“一个 Token 的 Embedding 就是它在任何句子里的最终含义。”——不对。Embedding 是初始表示，真正进入模型后还会结合上下文继续变化。
误解 03“只要把文本变成 Embedding，就已经匿名化。”——不能这样判断。Embedding 改变了数据形式，但是否还能关联、推断或还原原始内容，要结合具体模型、访问条件和使用方式判断。

六、为什么网信法研究者要知道 Embedding？

最直接的问题：数据变成“一串数字”，不等于法律上的风险已经消失。

在企业知识库、模型训练和AI服务中，文字、文档或用户内容可能被转换成 Embedding 后再保存或调用。从外观上看，它已经不再是一段可以直接阅读的文字，但法律判断不能停在“看起来不是原文”这一层。

真正需要继续追问的是：谁掌握生成这些数字的模型和技术条件？这些数字能否与原始文本、用户身份或其他数据重新关联？系统是否利用这些表示继续进行检索、分类、推荐或推断？因此，“向量化”“Embedding 化”首先是一种技术表示变化，而不是自动取得匿名化法律效果。

这也意味着，未来分析模型服务中的数据流时，不能只画“用户 → 模型”一条线。还要看数据是否被转换成 Embedding、保存在哪里、由谁控制、是否进入外部服务，以及这些表示后来被用于什么功能。

七、这一课只需要带走三句话

第一句

Embedding 是把 Token 变成一组可供模型计算的数字。

第二句

“向量”今天先理解成一组有顺序的数字；Token ID 是编号，Embedding 是实际参与计算的表示。

第三句：Embedding 会在训练中形成和调整，但它只是进入模型时的起点，之后还会随着上下文继续变化。

研究延伸

论文问题

语义表示转换与个人信息可识别性的规范判断

可以进一步研究：原始文本被转换为 Embedding 后，法律上应如何判断其个人信息属性？可识别性是否应当考虑模型持有情况、关联能力、还原成本、推断用途以及数据控制者实际能够调用的技术条件？

智库问题

政企AI知识库中的 Embedding 数据安全治理

可针对企业内部文档、政务材料和用户输入被转换成 Embedding 后的存储、调用、共享和外部模型接入问题，建立“原文—Embedding—检索结果—模型调用”的完整数据流审计要求。

原始材料
